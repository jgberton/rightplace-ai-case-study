# 🗄️ Database Architecture

> The database is not designed around tables or collections.
>
> It is designed around people, organizations and the relationships created throughout their professional journey.

# Overview

RightPlace AI stores long-term professional knowledge rather than temporary application data.

The database is organized around independent domains that evolve together while maintaining clear responsibilities.

This architecture allows candidates, organizations and AI-generated artifacts to grow independently without tightly coupling their data models.

  ```text
                         RightPlace Database

         Users ─────────────── Applications ─────────────── Jobs
           │                         │                        │
           │                         │                        │
           ▼                         ▼                        ▼
    Living Profile          Application Context       Organizations
           │                                                  │
           ▼                                                  ▼
 Generated Documents                              Shared Applications

                     Notifications are independent
```
# Design Principles

The database architecture follows a few fundamental principles.

- One source of truth for each entity.
- Long-term knowledge over temporary state.
- Domain-oriented collections.
- AI-generated artifacts remain separated from source data.
- Authentication is independent from business entities.
- Public and private data have different access patterns.

# Core Domains

The platform is organized around a small number of business domains.

| Domain | Responsibility |
|----------|----------------|
| Users | Professional identities and Living Profiles |
| Organizations | Companies and recruiters |
| Jobs | Published opportunities |
| Applications | Candidate-job relationships |
| Generated Documents | AI-generated resumes and cover letters |
| Notifications | Candidate communication |
| Shared Applications | Controlled sharing between organizations |

# Users

The Users domain represents professionals using the platform.

It stores long-term information that continuously evolves through conversations with North.

Unlike traditional recruitment systems, users are not represented only by resumes.

The Living Profile becomes the primary representation of professional understanding.

# Organizations

Organizations represent companies, recruiters and hiring teams.

Each organization owns its jobs, applications and internal hiring workflow.

This separation enables secure multi-tenant behavior throughout the platform.

# Jobs

Jobs describe hiring opportunities.

They contain structured hiring requirements and information generated during conversations with Job North.

Public job listings are intentionally separated from internal company information.

# Applications

Applications connect professionals and opportunities.

Rather than duplicating user information, applications reference existing candidate knowledge while adding opportunity-specific context.

This separation keeps professional understanding independent from individual hiring processes.

# Generated Documents

Documents generated by AI are stored independently from the Living Profile.

Examples include:

- ATS Resumes
- Cover Letters

These documents are considered translations of professional understanding rather than the understanding itself.

# Notifications

Notifications provide asynchronous communication across the platform.

Keeping notifications isolated avoids coupling communication history with business entities.

# Relationships

The overall data model can be represented as:

```text
User
   │
   ├──────────────► Living Profile
   │
   ├──────────────► Applications
   │                     │
   │                     ▼
   │                   Jobs
   │                     │
   │                     ▼
   │               Organizations
   │
   ├──────────────► Generated Documents
   │
   └──────────────► Notifications
```

The Living Profile acts as the long-term knowledge layer, while applications represent temporary hiring relationships.

# AI Integration

North continuously enriches user knowledge.

Instead of modifying generated documents directly, AI updates the Living Profile.

Career artifacts are regenerated whenever necessary from the latest understanding.

This keeps generated outputs synchronized without making them the source of truth.

# Security

Sensitive collections remain private.

Public information is intentionally projected into dedicated public collections when required.

This separation simplifies access control while reducing unnecessary exposure of internal data.

Authentication and authorization are enforced before any business data is accessed.

# Scalability

Collections are organized by business responsibility rather than feature.

This architecture allows individual domains to evolve independently as new platform capabilities are introduced.

Additional AI artifacts, hiring workflows and recommendation systems can be incorporated without restructuring the existing data model.

# Core Idea

The database is not a repository of resumes.

It is a repository of professional understanding.

Everything else is derived from that understanding.

> Knowledge persists.
>
> Artifacts evolve.
